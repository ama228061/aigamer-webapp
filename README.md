# AG — Агентство сельского хозяйства

Адаптивный сайт на HTML/CSS/JS для GitHub Pages. Изображения и основные материалы сохранены из предыдущей сборки Flutter. Dart-исходников в репозитории нет; новая версия редактируется напрямую в `index.html`, `styles.css` и `app.js`.

## Локальный запуск

Нужен Node.js 24.14 или новее. Сервер и API используют стандартные библиотеки, без runtime-зависимостей.

```sh
npm start
```

Сервер по умолчанию слушает только loopback на порту 8000. Он поддерживает `/` и `/aigamer-webapp/`. Если порт занят, используйте `PORT=8001 npm start`. Обрабатываются только публичные файлы сайта; сервер не отдаёт `.git`, `.env` или исходники API.

Для настоящих ответов добавьте `GEMINI_API_KEY` через защищённые настройки среды, а не в исходники или чат. По просьбе пользователя Worker и локальный API по умолчанию используют `gemini-3.1-flash-lite`; переменная `GEMINI_MODEL` позволяет выбрать другую модель. Доступность модели и бесплатные квоты нужно проверить в вашем проекте Google AI Studio: смена модели сама по себе не исправляет права ключа. Модель относится к семейству Gemini 3; адрес REST API остаётся `/v1beta/...:generateContent`.

Экономный режим ограничивает ответ 768 выходными токенами, использует минимальные рассуждения Flash и передаёт не больше пяти последних сообщений. Большой контекст дополнительно сокращается. Низкая температура не задаётся: используется рекомендованное для Gemini 3 значение по умолчанию. Это снижает расход, но не гарантирует бесплатность и не устанавливает общий суточный бюджет проекта. Автоматических повторов генерации и переключений на платную модель нет.

На 8 октября 2026 года [официальная таблица Google](https://ai.google.dev/gemini-api/docs/pricing) указывает бесплатные входные и выходные токены Standard Free Tier для `gemini-3.8-flash`, `gemini-3.5-flash-lite` и `gemini-3.1-flash-lite`. Это наличие тарифа, а не подтверждение доступа или ненулевой квоты конкретного проекта. Биллинг автоматически не включается. Workflow **Inspect Gemini free-tier availability** читает актуальные публичные тарифы и требования к ключам без генерации. Дополнительные короткие запросы к указанным бесплатным моделям запускаются только вручную с флажком `probe_free_access`, после проверки отсутствия биллинга у проекта.

## API для GitHub Pages

GitHub Pages публикует статические файлы и не исполняет серверный API. Для чата используется отдельный Cloudflare Worker (`worker.mjs`), вызывающий Gemini через общий обработчик `chat.mjs`.

Самый простой путь — подготовленный workflow **Connect Gemini 3 Worker**:

1. В [настройках Actions secrets репозитория](https://github.com/ama228061/aigamer-webapp/settings/secrets/actions) добавьте `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID` и `GEMINI_API_KEY`. Вводите значения только в защищённые поля GitHub. Cloudflare token должен иметь доступ к нужному аккаунту с правами Workers Scripts: Edit и Account Settings: Read. Account ID можно найти в панели аккаунта Cloudflare.
2. Workflow запускается при отправке изменений Worker или его настройки в `main`. После добавления или исправления секретов его можно запустить отдельно: Actions → **Connect Gemini 3 Worker** → Run workflow для ветки `main`.
3. Workflow проверит код и доступ ключа к метаданным выбранной модели без генерации. Затем развернёт Worker, загрузит ключ Gemini как Cloudflare secret и активирует публичный адрес `workers.dev`. Сначала он дождётся корректного CORS-ответа на OPTIONS: эти проверки не вызывают Gemini. Затем выполнит один короткий настоящий запрос. Только после успешного ответа Gemini 3 он запишет endpoint в `config.js`, отправит его в `main` и запросит сборку GitHub Pages.

Если ключ или модель недоступны, публичный endpoint не меняется. Workflow не включает оплату в Google и не меняет тариф аккаунта. Доступность бесплатной квоты проверьте в AI Studio до запуска.

С 28 мая 2026 года новые ключи AI Studio по умолчанию являются authorization keys, привязанными к сервисному аккаунту. Они зависят от прав этого аккаунта. Если метаданные модели доступны, но генерация возвращает `PERMISSION_DENIED`, проверьте права ключа и проекта. Для простой серверной схемы Google также поддерживает **standard API keys с явным ограничением API**: в Google Cloud → APIs & Services → Credentials выберите **Create credentials → API key**, создайте новый ключ без привязки сервисного аккаунта, затем установите **Application restrictions → None** и **API restrictions → Restrict key**. Разрешите именно сервис **`generativelanguage.googleapis.com`**: это адрес API, который вызывает Worker. Одного совпадения названия «Gemini API» в списке недостаточно для проверки нужного сервиса. Ограничение по HTTP referrer для запроса из Worker не подходит. Сохраните новый ключ только в существующем GitHub Actions secret `GEMINI_API_KEY`. Изменение ограничений старого ключа не меняет его тип. Неограниченные standard keys Google отклоняет. Подробности — в [официальной инструкции Google по ключам](https://ai.google.dev/gemini-api/docs/api-key).

Если проверка возвращает `API_KEY_SERVICE_BLOCKED`, ограничения ключа блокируют запрошенный сервис. Откройте [его точную страницу в API Library](https://console.cloud.google.com/apis/library/generativelanguage.googleapis.com), проверьте выбранный проект и разрешите этот сервис в API restrictions нового ключа. Если сервиса нет в списке, включите его в Library и обновите страницу настроек ключа. При изменении только ограничений значение ключа сохраняется: пересоздавать ключ или повторно обновлять GitHub Secret не нужно.

Если метаданные доступны, но генерация через Worker завершается ошибкой, workflow выполняет один диагностический запрос напрямую из GitHub Actions через тот же обработчик. Это позволяет сравнить доступ из Cloudflare и GitHub. Такая диагностика может расходовать токены; фактический расход успешного ответа выводится в Actions. В журнал ошибок попадают только фиксированные коды, без сообщений провайдера, ключей или данных проекта.

Для ручного развёртывания с собственной машины: `npm ci`, затем `npx wrangler login`, `npm run worker:deploy` и `npx wrangler secret put GEMINI_API_KEY`. Укажите адрес Worker в переменной `WORKER_URL` и выполните `node scripts/connect-pages.mjs`: endpoint сохранится только после проверки реального ответа. Затем отправьте `config.js` в `main`. Не передавайте прокси-placeholder из облачной среды как сырой ключ в Cloudflare; используйте защищённое поле Cloudflare или Actions secrets с настоящим ключом.

В `wrangler.jsonc` разрешён только origin `https://ama228061.github.io`. Для собственного домена настройте точный origin без пути и измените `SITE_ORIGIN` в `scripts/connect-pages.mjs`.

До настройки endpoint на GitHub Pages чат сообщает, что помощник не подключён. Локально пустой endpoint обращается к встроенному API. Браузер не отправляет cookie. Worker разрешает CORS только для настроенного сайта и ограничивает запросы до 5 в минуту на IP. CORS не является авторизацией; следите за квотой Gemini в своём аккаунте.

Старый JS-бандл содержал встроенный ключ API и удалён из текущей версии. Смените этот ключ у провайдера: удаление файла не убирает его из истории Git и ранее опубликованных копий.

## Проверки

```sh
npm test
npm run worker:check
```

Тесты проверяют маршрут HTTP, запросы Gemini с подставным ответом провайдера, историю диалога, ошибки, CORS, ограничения тела запроса и rate limit. `worker:check` собирает Worker без публикации и не проверяет реальный ключ.

В облачной среде доступен Python Playwright и Chromium. Для браузерной проверки без ключа:

```sh
PORT=8001 npm start
# В другой сессии:
python3 tests/browser_smoke.py
```

Браузерная проверка отдельно проверяет настоящий ответ локального API без ключа и сценарии чата с подставным API. Настоящая генерация Gemini требует настроенного ключа, разрешённой сети и отдельной проверки после развёртывания.

`flutter_service_worker.js` оставлен как миграционный worker: он удаляет только старые кеши Flutter и снимает свою регистрацию. Новая версия не зависит от Flutter, CanvasKit и Google Fonts.

## Скрытый журнал токенов

На странице нет счётчика или панели расхода. После запросов откройте Console в инструментах разработчика:

```js
AGRO_DEBUG.getTokenLog(); // Последние 100 запросов в этой вкладке
AGRO_DEBUG.summary(); // Суммы известных показателей и число запросов без измерения
AGRO_DEBUG.clear(); // Очистить журнал вкладки
```

В журнал попадают фактические `usageMetadata` от Gemini: входные токены, ответ, рассуждения, кешированные входные токены и общий расход. Общий расход берётся из `totalTokenCount`, а не вычисляется приблизительно. Если провайдер не вернул показатель, хранится `null`: это неизвестный расход, а не ноль. Данные вкладки очищаются при перезагрузке, сообщения и ключи не сохраняются.

Worker также пишет структурированные события `gemini_token_usage` в приватные Cloudflare Logs. В конфигурации включён сбор журналов. Они позволяют проверить расход после закрытия вкладки; доступ к ним требует авторизации в аккаунте Cloudflare. Workflow подключения выводит расход своего короткого проверочного запроса в Actions. Сам журнал и тесты не подтверждают наличие бесплатной квоты.
